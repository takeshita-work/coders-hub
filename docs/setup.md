# セットアップ手順

> **配布版（exe）の利用者向けの手順は、`specs/30-features/007-distribution/setup-flow.md` が正**（`claude mcp add` で登録する。ADR 0026・0027・0028）。この文書は、開発者向けの下書きで、`--mcp-config` 方式の記述は、古いので、順次 setup-flow.md に合わせる。

- 対象: セッション一覧（`specs/30-features/001-session-list`）、指示の送信（`specs/30-features/002-send-instruction`。「8. 操作モード」）、許可・質問への応答（`specs/30-features/003-permission-relay`。「9. 許可と質問に応答する」）
- 仕様との差分: `wait.mjs`（asyncRewake 方式）は「次」の段階。引数なしのチャネルサーバーは登録と生存確認だけ（ADR 0006）で、チャネル機能を宣言しないので、開発用フラグ（`--dangerously-load-development-channels`）は不要（T0-5 で確認）
- 実機での通し確認は、一覧が 001 の `acceptance.md`、指示の送信が 002 の `acceptance.md`、許可・質問への応答が 003 の `acceptance.md`（作成予定）。未確認の手順には「未確認」と書く

## 1. 準備（初回のみ）

```powershell
cd "D:\work\#tools\#web-app\coders-hub"
npm install
npm run build     # 画面をビルドする（dist/web/）。画面を変えたら再実行する
npm test          # 任意。全件が通ること
```

Node.js 22 以上が必要。

## 2. 設定を表示する

```powershell
node scripts/print-setup.mjs
```

このリポジトリの場所に合わせた、セットアップの手順（`setup-flow.md` の 3 つ: 登録・フック・起動と確認）が表示される。配布版では、案内のウィンドウのメニュー `1` で、同じ手順を 1 つずつ表示できる（ADR 0027）。

## 3. アカウントごとの設定（アカウントごとに初回のみ）

`CLAUDE_CONFIG_DIR` を切り替えて、アカウントごとに行う。

### 3-1. フック
表示された `hooks` を、そのアカウントの `settings.json`（`$env:CLAUDE_CONFIG_DIR\settings.json`）に追加する。すでに `hooks` がある場合は、イベントごとの配列に項目を足す。

使うフックは `SessionStart`、`UserPromptSubmit`、`PermissionRequest`、`PostToolUse`、`Stop`、`SessionEnd`。これらは `async: true` で、`claude` の動作を妨げない。

これに加えて、`PermissionRequest` に、質問（`AskUserQuestion`）へ答えるための同期フック（`matcher: "AskUserQuestion"`、`timeout` 100 秒）が表示される。ダッシュボードから質問に答えたいアカウントだけに追加する（手順 9）。答えがないときは何も出力せず、ターミナルの質問画面がそのまま出る。

### 3-2. チャネルサーバー
```powershell
$env:CLAUDE_CONFIG_DIR = "$HOME\.claude-account"
claude mcp add --scope user coders-hub -- node "D:/work/#tools/#web-app/coders-hub/src/channel/channel.mjs" --channel
claude mcp list
```
（実際のコマンドは手順 2 の表示をそのまま使う。**常に `--channel` つきで登録する**。操作モードで使うかどうかは、claude の起動時の開発用フラグで決まる。ADR 0026。未確認: `--scope user` がアカウントごとの設定に保存されること）

解除・やり直し: `claude mcp remove --scope user coders-hub`

## 4. 使い方

1. **Hub を起動する**（`npm start`。配布版は `coders-hub.exe` のダブルクリック）。チャネルサーバーは、Hub を起動しない（ADR 0020）。
2. `claude` を普通に起動する（開発用フラグも承認画面も要らない）。Hub が動いていなくても `claude` は妨げられず、Hub が動き始めたら一覧に出る。
3. ブラウザで `http://127.0.0.1:47766/` を開く。
   - ビルドしていない場合は、受け取った一覧を JSON で表示する簡易ページが出る。

Hub のポートは `127.0.0.1` の 47765（内部）と 47766（画面）。変えるときは、設定ファイルを使う（4-1）。

### 4-1. ポートを変える（設定ファイル）

既定の **47765（内部）・47766（画面）** は、Web 開発でよく使われるポートと重なりにくく、Windows が自動で割り当てるポート（49152 以降）とも重ならない（ADR 0019）。他のアプリと重なったときだけ、変える。

**配布版**: `coders-hub.exe` と同じフォルダに、`config.json` を作る（exe は、書き込めるフォルダに置く。リリースには `config.json` を含めない（見本の `config.example.jsonc` だけ）ので、更新で exe を置き換えても残る）。**開発版**（`node` で起動）: 既定ではファイルを読まない。使うときは、環境変数 `CODERS_HUB_CONFIG` にパスを指定する（ADR 0021）。

```json
{ "internalPort": 47765, "uiPort": 47766 }
```

コメント（`//`、`/* */`）を書ける（ADR 0023）。リリースの `config.example.jsonc` を `config.json` という名前でコピーして編集してもよい。

```powershell
# 例（配布版）: exe と同じフォルダで作って開く
notepad .\config.json
```

- どちらか片方だけでもよい。書いていないほうは既定値になる
- **優先順位: 環境変数 > 設定ファイル > 既定値**。環境変数 `CODERS_HUB_INTERNAL_PORT`・`CODERS_HUB_UI_PORT` は、一時的な上書き・テスト用
- 設定ファイルのパスは、環境変数 `CODERS_HUB_CONFIG` で変えられる（配布版でも使える）
- Hub・フック（`hook.mjs`・`ask-hook.mjs`）・チャネルサーバー（`channel.mjs`）の 3 つが、同じファイルを読むので、値がずれない
- 書き方が間違っているとき（JSON の誤り・ポートが 1〜65535 でない）は、Hub が、ファイルのパスを示して終了する
- **変えたあとは、動いている Hub を止めて（4-3）、起動し直す**。`netstat -ano | findstr 47765` で PID を調べ、`taskkill /F /PID <PID>`
- 画面の URL が変わる。折りたたみ・ソートの設定（localStorage）は、URL（ポート）ごとに分かれるので、引き継がれない
- **ポートは、一度決めたら変えない**（次の「アプリとしてインストール」は、URL に結びつくため）
- ポートがほかのアプリに使われていると、Hub は「すでに使われています」と出して終了する（NFR-005）。その場合は、番号を変える
- 旧版（8765 / 8766）から更新したとき: 新しい URL（`http://127.0.0.1:47766/`）を開く。旧ポートのままにするなら、設定ファイルに `8765` / `8766` を書く

### 4-2. アプリとしてインストールする（Chrome / Edge）

画面を、アドレスバーのない専用のウィンドウで開く。ブラウザの機能だけで、アプリの追加はいらない。

1. **Hub を起動しておく**（下の 4-3）
2. Edge / Chrome で `http://127.0.0.1:47766/`（設定ファイルで変えたときは、そのポート）を開く
3. インストールする
   - Edge: 「…」→「アプリ」→「このサイトをアプリとしてインストール」
   - Chrome: 「⋮」→「キャストの保存と共有」→「ページをアプリとしてインストール」（または「ショートカットを作成」→「ウィンドウとして開く」にチェック）
4. タスクバーやスタートメニューのアプリから開く

- アプリは、**インストールしたときの URL（ポート）を開く**。ポートを変えたら、入れ直す
- 要対応（許可待ち・質問待ち）の件数は、ウィンドウのタイトルに `(2) Coders Hub` のように出る（タスクバーでも確認できる）
- 画面の更新（再ビルド）は、アプリでも、ブラウザと同じく、Ctrl+F5 で再読み込みすると反映される

### 4-3. Hub を起動・終了する（ADR 0020）

アプリは、Hub が配信する画面を開くだけ。**Hub が動いていないと、画面は開けず、接続エラーになる**。Hub の起動と終了は、利用者が行う（`claude` は起動しない）。

| 操作 | 方法 |
|---|---|
| 起動（配布版） | `coders-hub.exe` をダブルクリックする。Hub は**ウィンドウなし**で動き、**案内のウィンドウ**（画面の URL・終了の方法・ログの場所）が出る。Enter で閉じる（閉じても Hub は動き続ける）。すでに動いていれば、その旨が出る。起動に失敗したときは、理由が出る |
| セットアップの手順を表示する | 案内のウィンドウのメニューで `1`（セットアップを進める。手順を 1 つずつ表示）、`2`（ログを開く）。ターミナルからは `coders-hub.exe setup \| more`。設定のファイル保存（`setup --write`）は、ADR 0028 でやめた |
| 起動（案内なし） | `coders-hub.exe start`。スタートアップ・タスク スケジューラ向け |
| 起動（開発版） | `npm start`（ターミナルを閉じると止まる）。ウィンドウなしなら、`node src/cli/main.mjs start` |
| 前面で動かす（調査用） | `coders-hub.exe hub`（ログが標準出力に出る。ターミナルから直接実行すると、配布版は出力が出ないので、`| more` を付ける） |
| ログオン時に自動起動する（任意） | スタートアップ（`shell:startup`）に `coders-hub.exe start` のショートカットを置く。または、タスク スケジューラで「ログオン時」に `coders-hub.exe start` を実行する（案内のウィンドウが出ない）。Hub が動いていれば何もしないので、重ねて登録しても問題ない |
| 終了 | 画面の「フィルター・ソート」のパネルの最下段「Hub を終了」。ほかに、タスクマネージャーで `coders-hub.exe`（開発版は `node.exe`）を終了する |

- ウィンドウなしの Hub のログは、`%LOCALAPPDATA%\coders-hub\hub.log` に追記される（1 MB を超えていたら、起動のときに作り直す）。起動しないときは、まずここを見る（設定ファイルの誤りなどの理由も出る）
- Hub を終了しても、動いている `claude` のチャネルサーバーは、Hub を起動し直さない。Hub を起動し直すと、動いているセッションが、自動で一覧に戻る
- **更新・ポートの変更・アンインストールは、Hub を終了してから行う**（動いている exe は上書き・削除できない）

アプリを先に開いてしまったときは、Hub を起動してから、アプリで再読み込み（F5）する。Hub が動いていない間の「接続が切れました」の警告は、画面が開いたあとに Hub が止まったときに出るもの。

## 5. 動作確認の方法（Hub 単体）

`claude` を使わずに、疑似フックを送って画面を確認できる。

```powershell
npm start
curl.exe -X POST http://127.0.0.1:47765/event -H "Content-Type: application/json" -d '{\"event\":\"UserPromptSubmit\",\"account\":\"acc\",\"input\":{\"session_id\":\"demo\",\"cwd\":\"D:/x\",\"prompt\":\"hi\"}}'
```

`event` を `PermissionRequest`、`Stop`、`SessionEnd` に変えると、表示が切り替わる。

## 6. 作業のまとめ

| タイミング | 作業 | 手動／自動 |
|---|---|---|
| 初回のみ | `npm install` | 手動 |
| アカウントごとに初回のみ | `settings.json` へのフック追加（質問用のフックを含む）、`claude mcp add` | 手動 |
| 毎回（または、ログオン時の自動起動を登録） | Hub の起動（`coders-hub.exe` のダブルクリック、`npm start`） | 手動（ADR 0020） |
| 毎回 | セッションの登録・状態の通知・終了検知 | 自動 |

## 7. うまくいかないとき

- 一覧に出ない: `http://127.0.0.1:47765/health` が `ok` を返すか確認する。`claude` で `/mcp` を開き、`coders-hub` が connected か確認する
- ポートがすでに使われている: 別のプロセス（前の実験の仮 Hub など）が使っている。止めるか、ポートを変える
- 状態が更新されない: 手順 3-1 のフックが、そのアカウントの `settings.json` に入っているか確認する
- 許可要求・質問がダッシュボードに出ない: 操作モード（手順 8）で起動しているか確認する。一覧だけのモードでは、許可待ち・質問待ちの表示は出るが、応答の操作はできない
- 質問に答えようとすると「時間切れ」になる: 質問が出てから約 85 秒（環境変数 `CODERS_HUB_ASK_WAIT_MS` で変更）のうちに答えなかった。ターミナルの質問画面に答えるか、もう一度質問してもらう
- 指示が「届いたか確認できません」になる: 開発用フラグ（`--dangerously-load-development-channels server:coders-hub`）を付けずに起動した可能性が高い。フラグがないと、サーバーは動くが、通知は黙って捨てられる（手順 8）

## 8. 操作モード（指示を送る）

ダッシュボードから、セッションへ指示を送れるようにする起動方法。一覧だけなら、手順 4 のままでよい。

### 8-1. 登録する
手順 3-2 の `claude mcp add` で、`--channel` つきのチャネルサーバーを登録しておく（アカウントごとに 1 回）。設定ファイル（`coders-hub-control.json` など）は、要らない。

### 8-2. 起動する
```powershell
claude --dangerously-load-development-channels server:coders-hub
```

- 起動のたびに、開発用チャネルの警告画面が出る。内容を確認して承認する
- フラグを付けずに起動すると、サーバーは動くが、通知は黙って捨てられる（エラーも警告も出ない。実機で確認済み）
- 起動用のスクリプトがあれば、既定のオプションに入れておくとよい。使わないセッションは、オプションなしで起動する

### 8-3. 使い方
- 一覧の行の「指示を送る」から入力して送る（Ctrl+Enter でも送れる）
- 返答待ちのセッションには、すぐ渡される
- 作業中・許可待ち・質問待ちのセッションへの指示は、保留される。返答待ちになったときに、1 件ずつ渡される。保留中は行に表示され、取り消せる
- 結果は、行に「届きました」などと表示される。画面を再読み込みすると消える
- 「指示として扱われませんでした」: 渡したタイミングが、ターミナルでの入力や作業と重なった。必要なら送り直す
- 本文の中の `</channel>` だけは、`<\/channel>` に置き換わって届く（`claude` の仕様）

### 8-4. 注意
- 操作できるのは、同じ PC の `127.0.0.1` からだけ。外部公開は別の機能（REQ-006）
- 画面からの書き込みは、他のサイトのページからは受け付けない（ADR 0012）

## 9. 許可と質問に応答する

ダッシュボードから、許可待ちのセッションに「許可」「拒否」を返し、質問待ちのセッションの質問に答えられる（機能 003）。操作モード（手順 8）で起動したセッションだけが対象。

### 9-1. 設定
- 許可の応答: 手順 8 の操作モードだけでよい（チャネルサーバーが許可中継も宣言する）
- 質問への回答: 手順 3-1 で追加した、`matcher: "AskUserQuestion"` の同期フックが必要。これがないと、質問は「質問待ち」と表示されるだけで、ダッシュボードからは答えられない（ターミナルで答える）

### 9-2. 使い方
- 許可待ちの行に、ツール名・説明・入力の内容が出る。「許可」「拒否」を押すと、すぐ（3 秒以内）セッションが再開する。拒否はモデルに伝わる
- 長い入力は折りたたまれる。`claude` が約 3,600 文字を超える入力を省略して渡すと、「途中が省略されています（省略: N 文字）」と出る。全文はターミナルで確認する
- 質問待ちの行に、質問と選択肢が出る。選択（複数選択可）か自由入力で答えて「回答する」を押す。すべての質問に答えるまで押せない
- ターミナルで先に応答すると、ダッシュボードの要求は閉じて「ターミナルで応答済み」と出る。ダッシュボードの応答が遅れても、二重に実行されたり、拒否が覆ったりしない
- 質問に約 85 秒答えないと「時間切れ」になり、ターミナルの質問画面が残る

### 9-3. 注意
- 許可の「今後は常に許可」のような永続化はできない。1 件ずつの許可・拒否だけ
- 質問への回答は、`PermissionRequest` フックの出力に依存する。`claude` の更新で形式が変わると、回答が通らなくなる可能性がある（その場合もターミナルで答えられる）
