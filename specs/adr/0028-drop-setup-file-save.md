# 0028: 設定のファイル保存（`setup --write`・メニューの 2）をやめる

- ステータス: Accepted
- 日付: 2026-10-12

## 背景
ADR 0025 で、案内のメニューに「設定をファイルに保存する」（`setup --write`）を付けた。保存するのは、`--mcp-config` に渡す JSON 2 つと、フックの JSON だった。

その後、次のことが変わった。

- ADR 0026: チャネルサーバーは `claude mcp add` で登録する。MCP の設定ファイル（`coders-hub.json`・`coders-hub-control.json`）は、不要になった
- ADR 0027: セットアップは、メニューで手順を 1 つずつ表示する。コピーできる内容は、メニューの `c` でクリップボードへコピーできる
- 手順 3 でコピーする枠（`{ "hooks": { ... } }`）は、保存されるフックの JSON と、同じ中身になった

残るのは、フックの JSON のファイル保存だけで、コピーと機能が重なっている。

## 選択肢
1. 残す（フックの JSON だけを保存する）
2. やめる

## 決定
2 を採用する。ユーザーの判断（2026-10-12）。

- `setup --write [--out <フォルダ>]` と、メニューの `2`（設定をファイルに保存する）をなくす。`coders-hub-hooks.json` は作らない
- メニューは、`1` セットアップを進める、`2` ログを開く、の 2 項目にする（ログは、`3` から `2` に繰り上がる）
- `setup`（テキスト）と `setup --json`（メニューが読む）は残す

ADR 0025 のメニュー `2` の部分と、AC-011-30 を、この ADR で置き換える。

## 理由
- 手順を表示して、コピーして貼る流れで足りる。同じ内容を出す手段が 2 つあると、文面や説明が重なる
- 保存したファイルは、exe のパスを含むので、exe を移動したら作り直しが要る。作らなければ、その手間もない

## 影響・トレードオフ
- 保存したファイルを、そのまま `settings.json` として使う手は、なくなる。手順 3 の枠を、コピーして貼る（ファイルがなければ、新しく作って貼る）
- 古い版で保存した `coders-hub-hooks.json` などは、使われなくなる。削除してよい
