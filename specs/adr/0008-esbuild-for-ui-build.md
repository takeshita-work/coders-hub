# 0008: 画面のビルドに Vite ではなく esbuild を使い、テストは node:test にする

- ステータス: Accepted
- 日付: 2026-10-08

## 背景
画面は React で作る（`specs/20-design/architecture.md`）。当初は React + Vite とし、テストに Vitest を想定していた。
しかし、リポジトリのパスに `#`（`D:\organization\works\#tools\#web-app\coders-hub`）が含まれており、実測で次の結果だった。

| 道具 | `#` を含むパスで |
|---|---|
| Vitest | 動かない（テストファイルが見つからない） |
| Vite の開発サーバー | 動かない（依存の解決に失敗する。Vite 自身も警告する） |
| Vite の本番ビルド | 動く |
| esbuild のバンドル（JSX 含む） | 動く |

リポジトリのパスは変えない（移動の手間が大きい）。

## 選択肢
1. リポジトリを `#` のない場所へ移し、Vite + Vitest を使う
2. Vite はビルドだけ使い、開発サーバーと Vitest は使わない
3. 画面のビルドに esbuild を使い、テストは `node:test`（Node 標準）にする

## 決定
3 を採用する。
- 画面のビルド: esbuild（React の JSX をバンドルして `dist/` に出す）。開発中の確認は、ビルドし直して Hub から配信する
- テスト: `node:test`。画面の部品は `react-dom/server` の描画結果で確認する
- 自動更新（HMR）は使わない

## 理由
- パスを変えずに、開発サーバーを除く全工程が動く
- 画面は一覧と数個の部品だけの小さなアプリで、HMR がなくても支障が小さい
- 依存が少なく、設定が短い。Hub 本体・フック・チャネルと同じテスト道具に揃えられる

## 影響・トレードオフ
- 画面の更新のたびにビルドが要る（esbuild は数十 ms）。ブラウザは再読み込みする
- 開発用の簡易サーバー（ビルド結果の配信）は Hub 本体の静的配信で兼ねる
- Vitest のモックや watch 機能がない。`node:test` の `mock` と `--watch` で足りる範囲に収める
- 後でパスを移す場合は、新しい ADR で Vite への切り替えを検討できる
