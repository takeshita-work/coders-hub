# 0022: 配布物は、zip にせず、exe などを個別の資産としてリリースに添付する

- ステータス: Accepted
- 日付: 2026-10-12

## 背景
ADR 0018 では、exe・README・LICENSE・SHA-256 を zip にまとめて、リリースに添付する形にした。

設定ファイル（`config.json`）を exe と同じフォルダに置く（ADR 0021）ことにしたため、次の問題が出た。

- 設定の見本を配りたいが、zip に `config.json` を入れると、新しい zip を前の場所に上書き展開したとき、**利用者が編集した設定が、既定の内容で上書きされる**
- 更新は、exe だけを置き換えれば足りる。zip を展開する手間が、不要

## 選択肢
1. zip のまま（`config.json` を入れない）
2. zip にしない。exe などを、個別の資産として添付する
3. 両方を添付する

## 決定
2 を採用する。ユーザーの選択（2026-10-12）。

- 添付する資産: `coders-hub.exe`（バージョンなしの固定名）、`config.example.json`（設定の見本。**読み込まれない**。使うときは `config.json` にコピーする）、`README.txt`、`LICENSE`、`THIRD_PARTY_NOTICES.txt`、`SHA256SUMS.txt`（exe の SHA-256）
- リリースに、`config.json` は含めない。名前が違う見本だけを配るので、更新で設定を上書きしない
- 固定名の exe により、`releases/latest/download/coders-hub.exe` が、常に最新を指す
- ライセンス表示（`THIRD_PARTY_NOTICES.txt`）は、資産として並べる。exe への埋め込みと `coders-hub.exe licenses` は、見送る（ユーザーの選択）
- zip は作らない。3 を採らないのは、どちらを使えばよいか迷うため

ADR 0018 のうち、zip で配る部分だけを、この ADR で置き換える（単一の exe、GitHub のリリース、タグでの自動化は維持）。

## 理由
- 入手が、exe のダウンロードと配置だけで済む。更新は、exe の置き換えだけ
- 設定の上書きの懸念が、構造的になくなる

## 影響・トレードオフ
- ダウンロードが、圧縮されない分、大きい（約 84 MB。zip の 2〜3 倍の見込み）
- 署名のない exe を直接ダウンロードすると、Edge / Chrome が「一般的にダウンロードされていない」と警告しやすい。「保持する」を選ぶ手間が増える（README に書く）。展開した exe にも、SmartScreen は出るので、zip でも避けられなかった
- exe 単体がコピーされると、ライセンス表示が離れる。同じリリースにあるので、実用上は問題ないと考える（埋め込みは見送り）
