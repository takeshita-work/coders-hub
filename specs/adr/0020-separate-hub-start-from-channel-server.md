# 0020: Hub の起動をチャネルサーバーから切り離し、exe のダブルクリックでウィンドウなしに起動する

- ステータス: Accepted
- 日付: 2026-10-12

## 背景
ADR 0004 では、チャネルサーバーが、Hub が動いていなければ Hub を起動した。配布版を実際の使い方（Chrome のアプリとして画面を開く）で考えると、次の問題がある。

- 動いている `claude` のセッションが 1 つでもあると、Hub を止めても、チャネルサーバーが数秒で起動し直す。**止められない**
- そのため、exe の更新（実行中のファイルは上書きできない）・ポートの変更・アンインストールができない
- Hub を `claude` が起動するので、利用者は、いつ誰が起動したか分からない
- 停止の仕組み（停止の依頼・再起動を抑える状態）を足すと、動作が 2 通りになり、仕様・実装・テスト・文書が複雑になる

ユーザーの要望（2026-10-12）: Hub の起動は利用者が決める。セッションにチャネルサーバーを付けるかも利用者が決める（`--mcp-config`）。exe のダブルクリックで、ウィンドウなしに起動したい。

## 選択肢
1. 自動起動を残し、`stop` と「停止中の状態」を足す
2. 自動起動をやめ、Hub の起動と停止を利用者に任せる（`autoStartHub` のような設定も作らない）
3. 2 に加えて、設定で自動起動を選べるようにする

## 決定
2 を採用する。

- **チャネルサーバーは、Hub を起動しない**。Hub がなくても落ちず、`claude` を妨げない。Hub が動き始めたら、再接続して登録する（NFR-004 の復元と同じ経路）。フックも、これまでどおり、失敗しても黙る
- **Hub の起動**: 利用者が行う。`coders-hub.exe`（引数なし。ダブルクリックを含む）または `coders-hub.exe start` が、Hub をウィンドウなしで、切り離して起動し、すぐ終了する。すでに Hub が動いていれば、何もしない（ポートの排他。NFR-005）。ログイン時の自動起動は、利用者が Windows のスタートアップ・タスク スケジューラで登録する（本アプリは登録しない）
- **前面で動かす**: `coders-hub.exe hub`。ログは標準出力へ出る（確認・不具合調査用）
- **ログ**: ウィンドウなしの Hub の出力は、`%LOCALAPPDATA%\coders-hub\hub.log` に追記する。起動のとき、1 MB を超えていたら作り直す
- **ウィンドウなしの exe**: 配布版の exe は、ビルドのとき、PE ヘッダーのサブシステムを GUI（ウィンドウなし）に書き換える。実機で、パイプ経由の標準入出力（`version`・`hook`・`channel` の MCP）が動くことを確認した（2026-10-12）。ターミナルで直接実行すると、出力が画面に出ない（GUI アプリは、親のコンソールに出力しない）ので、`coders-hub.exe setup | more` のように、パイプへ渡す。開発時の `node` は影響を受けない
- **画面からの終了**: `POST /api/shutdown`（画面側。ADR 0012 の保護あり）。応答を返してから、Hub が終了する。画面の「フィルター・ソート」のパネルに、「Hub を終了」を置く（確認つき）。再起動は画面からはできない
- 作らないもの: 自動起動の設定、`stop` サブコマンド、起動時にブラウザを開く動作

ADR 0004 のうち、「チャネルサーバーが Hub を起動する」部分を、この ADR で置き換える（単一プロセス、ポート 1 組、ロングポーリングは維持）。ADR 0018 の「Hub の自動起動」も、同様。

## 理由
- 止めても再起動されない。更新・ポート変更・アンインストールが、Hub を止めるだけでできる
- 起動と停止の責任が、利用者の側にそろう。動作が 1 通りで、テストと文書が少ない
- 画面は Hub が配信するので、Hub の終了も、画面から行える

## 影響・トレードオフ
- **初めて使う人は、Hub を自分で起動する必要がある**。README の最初の手順に入れる
- Hub が止まっているとき、画面は、ブラウザの標準のエラー画面になる。専用の案内は出さない（Service Worker を使わない）
- ウィンドウなしの Hub は、終了のウィンドウがない。画面の「Hub を終了」か、タスクマネージャーで止める
- GUI の exe は、ターミナルの直接実行で出力が出ない。`setup` などは、パイプへ渡す
- 旧版の利用者は、Hub を手動で起動する形に変わる
