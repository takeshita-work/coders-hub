# 0024: exe のダブルクリックでは、案内のウィンドウ（URL・終了の方法）を出し、Enter で閉じる

- ステータス: Accepted
- 日付: 2026-10-12

## 背景
ADR 0020 では、`coders-hub.exe`（引数なし）を、ウィンドウなしで Hub を起動して、すぐ終了する動作にした。実際にダブルクリックしてみると、**何も表示されず、起動できたか、画面の URL はどれか、どう終了するかが分からない**（ユーザーの指摘、2026-10-12）。設定ファイルの誤りで起動できないときも、理由が見えない（`hub.log` を開くまで分からない）。

一方、Hub 自体は、ウィンドウなしで動き続けてほしい（ウィンドウを閉じて止まる運用は、ADR 0020 で避けた）。

## 選択肢
1. 何も出さない（ADR 0020 のまま）
2. 引数なしのときだけ、案内のウィンドウを出す。Hub はウィンドウなしで動き続け、案内は Enter で閉じる。`start` は、案内なしのまま
3. Hub 自体を前面（コンソールのウィンドウ）で動かす（閉じると止まる）

## 決定
2 を採用する。ユーザーの選択（2026-10-12）。

- **引数なし（ダブルクリック）**: Hub を起動（すでに動いていれば何もしない）し、応答を待って（最長 5 秒）、案内のウィンドウを出す。案内の内容: 起動した／すでに起動している／応答が遅い／起動できなかった（理由つき）、画面の URL と内部 API の URL（説明は付けない）、Hub の終了方法（「Hub を終了するには、アプリにアクセスし終了してください」）、ウィンドウを閉じても Hub は動き続けること、ログの場所、「Enter キーを押すと、このウィンドウを閉じます」
- **`start`**: 案内を出さない。ログオン時の自動起動（スタートアップ・タスク スケジューラ）は、`coders-hub.exe start` を登録する（毎回ウィンドウが出ないように）
- **表示の方法**: 配布版の exe は、ウィンドウのない形式（ADR 0020）で、自分ではコンソールを持てない。そこで、本文を UTF-8 のファイルに書き、`cmd.exe /c start` で、別の新しいコンソールのウィンドウに、バッチ（PowerShell で本文を表示し、`Read-Host` で Enter を待ち、`exit`）を開く。cmd の `type` は、`chcp 65001` のとき、末尾の日本語の 1 文字が文字化けしたため使わない（PowerShell は、コンソールに UTF-16 で書くので、コードページに依存しない）。ファイルは `%LOCALAPPDATA%\coders-hub\guide.txt` / `guide.cmd` に、固定の名前で上書きする（増えない）。本文をコマンドの引数に載せないので、`&` や `%` のエスケープが要らない。PowerShell のコマンドは固定の文字列で、`-EncodedCommand` は、ウイルス対策ソフトの誤検知を招きやすいので使わない
- **開発時（`node` で起動）**: 案内は、そのターミナルに出す（別のウィンドウは開かない）
- 案内のウィンドウを閉じても（Enter でも、×でも）、Hub は止まらない

ADR 0020 のうち、「引数なしは `start` と同じ」の部分を、この ADR で置き換える（Hub のウィンドウなしの起動、画面からの終了は維持）。

## 理由
- ダブルクリックの結果（起動した・すでに動いている・失敗した）と、次にすること（URL、終了の方法）が分かる
- 起動に失敗したとき、理由がその場で見える（これまでは `hub.log` を開く必要があった）
- Hub のウィンドウを閉じて止まる運用にしないので、うっかり閉じても Hub は止まらない

## 影響・トレードオフ
- ダブルクリックのたびに、案内のウィンドウが開く。うるさければ、`start` のショートカットを使う（README に書く）
- 案内は `cmd` のウィンドウ（既定のターミナルによっては Windows Terminal のタブ）で出る。表示の見た目は、利用者の環境のターミナルに従う
- 案内の表示のために、`cmd.exe` を起動する。誤検知の可能性は低いが、ゼロではない
