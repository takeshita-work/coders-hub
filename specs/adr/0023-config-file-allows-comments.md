# 0023: 設定ファイル（config.json）には、JSONC のコメントを書けるようにする

- ステータス: Accepted
- 日付: 2026-10-12

## 背景
設定の見本（ADR 0022 では `config.example.json`）に、使い方の説明を入れたい。JSON にはコメントがないので、説明用のキー（`"_説明": "..."`）を入れる案が出たが、設定の中身に説明が混ざり、見づらい（ユーザーの指摘、2026-10-12）。

## 選択肢
1. 説明用のキー（`_説明`）を JSON に入れる
2. 見本だけ、コメントつきの JSONC にする。`config.json` は、コメントなしの JSON のまま
3. `config.json` も JSONC として読み、コメントを書けるようにする。見本は `config.example.jsonc`

## 決定
3 を採用する。

- **読み込み**: `config.json` の `//` の行コメントと `/* */` のブロックコメントを無視する。文字列の中の `//` は、コメントではない。先頭の BOM（メモ帳などが付ける）も無視する。独自の小さな処理（依存なし）で実装し、コメントは空白に置き換える（行数が変わらず、エラーの位置がずれない）
- **見本**: `config.example.jsonc`（コメントつき）。Hub は読まない。使うときは `config.json` という名前でコピーする。リリースの資産にも、この名前で添付する（ADR 0022 の `config.example.json` を、この名前に置き換える）
- 読み込むファイルの名前は `config.json` のまま（ADR 0021）。末尾のカンマ（trailing comma）は許さない
- 壊れた JSON のエラーの扱いは、ADR 0019 のまま（ファイルのパスを示す）

## 理由
- 見本のコメントを、そのまま `config.json` に残して編集できる（コピーしたあと、コメントを消す手間がない）
- 設定の中身（キー）に、説明が混ざらない

## 影響・トレードオフ
- エディタによっては、`.json` のコメントを警告で示す（VS Code は `.json` のコメントを許すか、ファイルの種類による）。動作には影響しない。見本は `.jsonc` なので、色分けされる
- 読み込みの処理が、標準の `JSON.parse` だけでなくなる（約 25 行）。テストで固定する
