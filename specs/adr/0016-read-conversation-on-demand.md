# 0016: 会話は、画面から要求されたときに会話ログから読み、Hub は保持しない

- ステータス: Accepted
- 日付: 2026-10-11

## 背景
機能 004（REQ-007）で、詳細に直近の会話（利用者の発言と Claude の応答）を出す。会話の本文は、`claude` が書く会話ログ（JSONL。各セッションの `transcript_path`）にある。

次の制約がある。

- Hub は、状態・イベント・指示の履歴を保存しない（NFR-009）。会話の本文は、機密を含みやすい
- 会話ログは内部フォーマットで、バージョンアップで変わりうる（NFR-008）。ADR 0007 で、JSONL は補助用途に限定した
- 会話ログは大きくなる（実機で、この開発セッションの分が 11 MB）。全部は読めない
- 会話の読み取りは、書き込みより情報が漏れやすい（他のサイトのページから叩けると、会話を読まれる）

実機で、会話ログの形式を確認した（2026-10-11）。1 行 1 レコード。`user`（文字列、またはツールの結果）、`assistant`（`text`・`thinking`・`tool_use`）、`system`・`attachment` などがあり、`assistant` の `message.model` にモデル名が入っている。

## 選択肢
1. Hub が会話をメモリに持ち、WebSocket で配信する（常に読み続ける）
2. Hub がファイルの変更を監視して、変更を通知（ヒント）だけ送り、本文は画面から要求させる
3. 画面から要求されたときに、Hub が会話ログの末尾から必要な分を読んで返す。保持しない。画面は、詳細を開いている間だけ、条件つきで繰り返し取得する

## 決定
3 を採用する。

- 取得 API: `GET /api/sessions/:sessionId/conversation`。クライアントはセッション ID だけを渡す。読むファイルは、Hub がフックで受け取った `transcript_path`、なければ `<CLAUDE_CONFIG_DIR>/projects/*/<sessionId>.jsonl` を探す。クライアントからパスは受け取らない
- 読み方: 末尾から、必要な件数が取れるまで、ブロック単位で読む（1 回の取得で読む量には上限がある）。さらに前を読むときは、前回の読んだ位置（カーソル）を渡し、そこから前へ読み進める。件数の上限は設けない。会話の記録のうち、利用者の発言・応答のテキスト・ツールの使用の要約・`AskUserQuestion` だけを取り出す。思考、ツールの入力・出力、サブエージェント、システムの記録は捨てる。壊れた行は飛ばす
- **保持しない**: 読んだ内容は、返したら捨てる。キャッシュしない。変更の有無は、ファイルの更新時刻とサイズで判断し、`ETag` で条件つきの取得にする（変更がなければ 304 で本文を返さない）
- 更新: 画面は、詳細を開いている間、数秒ごとに条件つきで取得する。詳細を開いていないセッションは読まない
- **読み取りにも、書き込みと同じ保護を付ける**（ADR 0012）: `Host` の検査、`Origin` があれば同じオリジン、独自ヘッダー `X-Coders-Hub: 1` が必要。独自ヘッダーは、他のサイトからの読み取りを事前確認（preflight）で止める
- 会話ログが読めない・形式が想定外のときは、会話の取得だけが失敗する（`{ error }` で、画面は「会話を読み込めません」と出す）。状態・許可・質問・指示は影響を受けない

## 理由
- 本文を Hub が持たないので、NFR-009 を守れる。Hub の再起動や、メモリの使用量とも無関係
- 変更を通知する仕組み（1・2）を作らなくても、詳細を開いている間だけ取得すれば足りる（利用者は、同時に 1 つのセッションしか詳細を開かない）。30 セッションでも、読むのは 1 つだけ
- 末尾だけ読むので、大きなログでも 1 秒以内に収まる見込み。ADR 0007 の末尾読みの部品を共通にできる
- 読み取りの保護を、書き込みと同じ仕組みにできる

## 影響・トレードオフ
- 反映の遅れは、取得の間隔（数秒）とログの書き込みの遅れ。NFR-003（3 秒以内）に収まるよう、間隔を調整する。取得のたびにファイルの末尾を読むので、詳細を開いている間は小さな負荷がある
- 会話ログの形式が変わると、会話の表示だけが壊れる（NFR-008）。他の機能は影響を受けない
- 取得の応答には会話の本文が含まれる。`127.0.0.1` だけで待ち受け、上記の保護を通ったものにだけ返す。外部公開（REQ-006）のときは、認証を足すまで、会話の取得も公開しない
- 結果の行（許可・質問の内容）を会話に残す表示は、この API が返す会話のツール行・質問の行で実現できる（機能 006 の結果の行は、ブラウザのメモリ内のまま）
- 会話ログの `message.model` から、モデル名を取れる。モデル名の表示は、別の検討とする
