# 0010: モデルからの質問で待つ状態を「質問待ち」として、4 つ目の状態にする

- ステータス: Accepted
- 日付: 2026-10-08

## 背景
状態は「作業中／返答待ち／許可待ち」の 3 つとしていた（`glossary.md`）。
実機で、モデルがツール `AskUserQuestion` で利用者に質問してきたとき、次のことが分かった。

- フックは `PermissionRequest`（`tool_name` が `AskUserQuestion`）が発火する。画面では「許可待ち」（赤）になる
- `claude` の状態ファイルは、`waiting`／`waitingFor: input needed`（ツールの許可は `permission prompt`）

質問は、ツールの実行を許可するかどうかではなく、モデルへの回答を求めるものなので、「許可待ち」という表示は実態と合わない。

## 選択肢
1. 返答待ちとして表示する
2. 許可待ちのままにする
3. 「質問待ち」を 4 つ目の状態にする

## 決定
3 を採用する。

- 状態: `question`（表示は「質問待ち」）。許可待ちと同じく、人の応答で止まっている状態
- 判定: フックの `PermissionRequest` で `tool_name` が `AskUserQuestion` なら質問待ち、それ以外は許可待ち。状態ファイル（ADR 0009）は `waitingFor` が `input needed` なら質問待ち、それ以外の `waiting` は許可待ち
- 復帰: `PostToolUse` で作業中へ（許可待ちと同じ）。拒否・Esc の補正（ADR 0007、ADR 0009）の対象にも含める
- 並び順: 許可待ち → **質問待ち** → 返答待ち → 作業中
- 要対応: 許可待ち・質問待ち・返答待ち（作業中以外）。件数サマリー、タブのタイトル、「要対応のみ」の絞り込みの対象
- 表示: 紫系の背景と左の太線、サマリーとグループのバッジも紫系

ADR 0009 の「`waiting` はすべて許可待ちとして扱う」を、この決定で上書きする（状態ファイルによる補正の方式そのものは変わらない）。

## 理由
- 利用者にとって、「許可を求められている」と「質問に答える必要がある」は別の行動で、区別できると便利
- 判定に必要な情報（`tool_name`、`waitingFor`）は、すでに取れている

## 影響・トレードオフ
- 状態が 3 つから 4 つになる。`glossary.md`、`vision.md`、REQ-001・010、`spec.md`（AC-001-10 を追加）、画面の方針、状態モデル、plan を更新した
- 質問待ちにならない質問（例: プラン承認の `ExitPlanMode`）があるかは未確認。`PermissionRequest` の `tool_name` が `AskUserQuestion` 以外なら、許可待ちとして表示される。実機で見つかったら、判定を足す
