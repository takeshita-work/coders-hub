# 0006: MVP の生存確認にチャネルサーバーを使う

- ステータス: Accepted
- 日付: 2026-10-08

## 背景
MVP はフックだけで状態を取得する（ADR 0003）。しかしフックだけでは、強制終了したセッションを検知できない（SessionEnd は正常終了時にしか来ない）。
NFR-006 は、閉じたセッションを 1 分以内に一覧から外すことを求めている。

## 選択肢
1. チャネルサーバーだけ MVP に入れ、ロングポーリングを生存確認に使う
2. 本体が `claude` の PID を定期確認する
3. 最終イベントからの経過時間で判定する
4. 強制終了は検知しない（NFR-006 を緩める）

## 決定
1 を採用する。MVP からチャネルサーバー（`channel.mjs`）を入れ、ADR 0004 のロングポーリング（約 30 秒）を生存確認と自己登録に使う。
MVP では指示送信・許可応答は行わない。チャネルサーバーは登録と生存確認だけを担う。

## 理由
- 元の設計（ADR 0004）の仕組みをそのまま使える。本体の再起動後も一覧が自動で復元される（NFR-004）
- PID 確認のように、Windows 固有の実装を足さずに済む
- 「次」の段階で Channels を使う指示送信・許可応答を足すとき、同じ部品を拡張できる

## 影響・トレードオフ
- MVP から `--mcp-config` を付けた起動が必要になる（起動用の関数が必要）
- チャネル機能（`claude/channel`）を宣言する場合は、`--dangerously-load-development-channels` と起動時の警告画面の承認が MVP から必要になる
- 要検証: チャネル機能を宣言しない通常の MCP サーバーとして起動すれば、MVP の間は開発用フラグと警告画面なしで生存確認だけ行えるか。行えるなら、MVP ではそちらにして、「次」の段階でチャネル機能を宣言する
- 要検証: Windows のターミナル版で、MCP サーバーが `CLAUDE_CODE_SESSION_ID` を受け取れるか
