# 0017: 応答の Markdown は、marked で字句解析し、React の要素に組み立てて整形する

- ステータス: Accepted
- 日付: 2026-10-11

## 背景
機能 004 の会話の表示で、Claude の応答は Markdown で書かれている（見出し・箇条書き・コードブロック・表・リンクなど）。最初は、文章をそのままの文字として出していたが、見づらいという要望があった。

整形には、次の制約がある。

- 会話の本文は、信頼できない入力として扱う（ツールの出力や、外部の文章を引用していることがある）。Markdown に含まれる HTML・スクリプト・`javascript:` のリンクは、実行されてはいけない
- Hub と画面は、依存を増やしすぎない。画面は esbuild でひとつにまとめて配信する（ADR 0008）

## 選択肢
1. `marked` で HTML 文字列を作り、`dangerouslySetInnerHTML` で出す（`DOMPurify` などで無害化する）
2. `react-markdown`（`remark` 系）を使う
3. `marked` は字句解析（トークン化）にだけ使い、トークンから React の要素を自分で組み立てる。HTML 文字列は作らない
4. 自前で Markdown を解析する

## 決定
3 を採用する。

- 依存は `marked`（字句解析のみ）。React の要素への変換は、`src/web/markdown.mjs`（約 100 行）に持つ
- `dangerouslySetInnerHTML` を使わない。文章の中の HTML（`html` トークン）は、解釈せず、文字として出す
- リンクは `http(s)` と `mailto` だけ。新しいタブで開き、`rel="noopener noreferrer"` を付ける。それ以外（`javascript:`・`data:` など）は、リンクにしない。画像は読み込まず、代わりの文字だけを出す
- 対象は、Claude の応答だけ。利用者の発言（ダッシュボードから送った指示を含む）は、書いたとおりの文字で出す
- 同じ本文は、再描画のたびに解析し直さない（本文が変わるまで、結果を使う）

## 理由
- HTML 文字列を作らないので、無害化の漏れによる XSS が起きにくい（構造上、スクリプトを作れない）
- `react-markdown` より依存が少なく、画面に出す要素と見た目（クラス）を、こちらで決められる
- 自前の解析は、表・入れ子の箇条書き・コードブロックの端の例が多く、不具合が出やすい。字句解析は、実績のあるライブラリに任せる

## 影響・トレードオフ
- 対応する記法は、`marked` の字句解析（GFM）が出すもの。変換が未対応のトークンは、元の文字のまま出す。シンタックスハイライト（言語ごとの色付け）はしない
- 画面のビルドの大きさが、`marked` の分だけ増える（約 40 KB 圧縮前）
- Markdown の見た目（見出し・表・コードの CSS）を、画面で持つ
