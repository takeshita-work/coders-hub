# 0009: 状態のずれの補正に、claude 自身の状態ファイル（sessions/<pid>.json）の status を使う

- ステータス: Accepted
- 日付: 2026-10-08

## 背景
状態の取得はフックで行い（ADR 0003）、拒否・中断のずれは会話ログ（JSONL）の定期確認で補う（ADR 0007）。
実機の手動テストで、ADR 0007 が拾えない場合が見つかった。

- 通常の作業中（許可ダイアログなし）に **Esc で早く止める**と、会話ログに中断の記録が書かれないことがある（実測: 送信の 1 秒後に Esc → 記録なし。6 秒後に Esc → 記録あり）。フックも `Stop` を含め何も来ない。そのため、Hub の状態が「作業中」のまま残る（13 分以上続いた）。

一方、`claude` が各アカウントのフォルダ（`<CLAUDE_CONFIG_DIR>/sessions/<pid>.json`）に書く状態ファイルには、`status` が正しく出ていた（実機で記録）。

| `status` | 意味（実測） |
|---|---|
| `busy` | 処理中（依頼の送信、許可後） |
| `idle` | 待機中（回答の完了、Esc で止めた直後） |
| `waiting`（`waitingFor`: `permission prompt` / `input needed`） | 許可ダイアログ／モデルからの質問（`AskUserQuestion`）の待ち |

更新は、`statusUpdatedAt`（ミリ秒）つき。変化から 0.1〜0.3 秒以内に書かれていた。ファイルには `sessionId`・`pid`・`cwd`・`name` なども入っている。

## 選択肢
1. 割り切る（通常の作業中の Esc は直らないものとする。経過時間で気づいてもらう）
2. 状態ファイルを、フックの補正に使う
3. 状態ファイルを主にし、フックをやめる
4. 一定時間、フックの合図がなければ「要確認」にする

## 決定
2 を採用する。Hub は、約 0.5 秒ごとに、Hub が把握しているセッションのアカウントの `sessions/*.json` を読み、`status` を状態に対応づけて補正する。

- 対応: `busy` → 作業中、`idle` → 返答待ち、`waiting` → 許可待ち（質問待ちも含む）
- **フックで分かっている状態より新しい変化だけ**を採用する（`statusUpdatedAt` が `stateSince` より後のとき）。古い値で、フックの結果を上書きしない
- Hub の再起動後に、推測で「返答待ち」と置いたセッション（`unverified`）は、時刻を問わず実際の状態で置き換え、`stateSince` も `statusUpdatedAt` にする。再起動後の「いつから」が正しくなる
- 状態の主は、引き続きフック（ADR 0003）。読めない・形式が違う・`status` がない場合は、何もしない
- ADR 0007（会話ログの確認）は、そのまま残す。両方とも補助で、どちらかが先に直せば、もう一方は何もしない

## 理由
- 通常の作業中の Esc は、フックにも会話ログにも出ないことがある。状態ファイルなら、実機で確認できた
- 状態ファイルは `claude` 自身が書くので、Esc・拒否・中断のどれでも、`idle` に落ちる（実測: 通常の作業中の Esc 2 回、許可ダイアログでの拒否 1 回。拒否では `waiting`（permission prompt）から `idle` に直接変わった）
- 実装後の手動テストで、1〜2.5 秒後の Esc でも、画面が約 1 秒で返答待ちに戻ることを確認した
- 再起動後の復元の精度が上がる

## 影響・トレードオフ
- 非公開のファイルで、バージョンアップで形式が変わりうる（NFR-008）。変わっても、補正ができなくなるだけで、フックによる状態は動く。使っている項目は `sessionId`・`status`・`statusUpdatedAt` の 3 つだけ
- `waiting`（質問待ち）も許可待ちとして扱う。画面上は「許可待ち」だが、モデルからの質問のときもある（フックの `PermissionRequest` も、`AskUserQuestion` で発火するため、すでに同じ扱い）
- ファイルを全セッション分、定期的に読む（30 セッションでも 1 秒に数十回の小さな読み取り）
- この仕組みは、フックを使っていない `claude`（チャネルサーバーなし）の発見には使わない（今回は補正のみ）。状態ファイルには、Hub が知らないセッションも載っている。一覧に自動で加える案は、今後の検討（`open-questions.md`）
