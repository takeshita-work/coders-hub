# 0015: 画面を「サイドバー（ツリー）＋詳細」にし、許可・質問は会話の中で応答する

- ステータス: Proposed
- 日付: 2026-10-11

## 背景
機能 001〜003 で、画面は「アカウントごとのグループに、セッションの行が並ぶ一覧」になっている。指示の入力・許可要求・質問も、一覧の行に展開して出す作りだった。実機で使うと、次の問題が出た。

- 行に情報が増え（状態・経過時間・発言・指示欄・許可要求・質問）、30 セッションを見渡しにくい
- スマホの幅では、行の中の操作（ボタン・入力欄）が窮屈になる（NFR-010 のスマホ対応は、外部公開と同時に先送りされていた）
- 並びが「状態順」だけで、位置が状態の変化のたびに動く。同じセッションを探し続けにくい
- 返答待ちを「要対応」として強調したが、実際には「指示を待っているだけで何もしていない」状態で、強調するほどのものではない

HTML の試作（`specs/20-design/screens/mockup/index.html`）で、画面の構成を作って確認した。この ADR は、その構成を採用する判断を記録する。

## 選択肢
1. 現状の一覧のまま、行の見た目だけを整える
2. サイドバー（アカウント → プロジェクト → セッションのツリー）と、選んだセッションの詳細（メイン）に分ける。スマホでは、一覧と詳細を別画面にする
3. セッションごとにタブやカードを並べる（ダッシュボード型）

## 決定
2 を採用する。主な内容は次のとおり。

- **構成**: 左にサイドバー、右にメイン（詳細）。幅 800px 以下では、一覧と詳細を別画面にする（詳細に戻るボタンを出す）
- **ツリーの並び**: アカウント（起動が最も早いセッションを持つ順）→ プロジェクト（名前順。昇順／降順を切り替え）→ セッション（起動順。早い順／遅い順を切り替え）。**状態では並べ替えない**。位置が状態で動かない
- **状態の表現**: 行の左の太線の色が状態、背景が操作できるか（できない＝グレー）。許可待ち・質問待ちは札を出し、アカウントの帯とプロジェクトに件数のバッジを出す。**返答待ちは、何もない状態として、札も強調もしない**。「要対応」は、許可待ちと質問待ちを指す
- **絞り込み**: 「操作できるものだけ」のスイッチだけ。状態での絞り込み・検索・件数サマリーはやめる（30 セッション程度なら、ツリーの折りたたみで足りる）。ソートと絞り込みの設定は、見出しのボタンで開くパネルに集める
- **サイドバーでの操作**: 短い許可要求（入力が 200 文字以下で省略なし）の「許可」だけは、サイドバーの行からできる。拒否と、長い入力や質問への応答は、詳細で行う（内容を見てから判断するため）
- **詳細の構成**: 見出し（プロジェクト名・アカウント名）は固定せず、会話と一緒にスクロールする。スクロールバーは画面の右端に、上から下まで出す。下部は固定で、メッセージ入力欄（送信ボタンなし。Enter で送信、Shift+Enter で改行。1 行から始まり 20 行で内部スクロール）と、その下に状態の行（ID・経過時間・状態）を出す
- **許可要求・質問・指示は、会話の中に出す**: 応答待ちの許可要求・質問は、会話の末尾（最新の位置）にカードで出す。応答したあとは、状態の色で右寄せの結果の行にして残す。保留中の指示と、渡した指示（届きました）も、会話の中に時系列で出す。下部に固定するのは入力欄だけ。要求が画面の外にあるときは、「一番下へ」ボタンで戻れる
- **セッションの起動時刻 `startedAt` を Hub が持つ**: 起動順の並びのため。取得元は、`claude` の状態ファイル（`sessions/<pid>.json`）の `startedAt`（実機で確認済み、ミリ秒）。ADR 0009 と同じ非公開ファイルに依存するので、読めないときは、Hub が初めてそのセッションを見た時刻で代用する

## 理由
- 一覧（見渡す）と詳細（操作する）で役割が分かれ、30 セッションでも見やすく、操作は 1 つのセッションに集中できる
- 状態で並べ替えないので、行の位置が安定する。状態は色と札で分かる
- 狭い幅でも、一覧と詳細を別画面にすれば、同じ部品で成り立つ（スマホ専用の画面を作らない）
- 許可・質問・指示を会話に時系列で並べると、「いつ何を許可し、何と答えたか」が会話の流れとして読める。要求が下部に固定されて、会話の流れから切り離される問題がない
- 返答待ちの強調をやめると、本当に対応が要る許可待ち・質問待ちが目立つ

## 影響・トレードオフ
- **要件の変更**: REQ-010（要対応の強調）の対象から返答待ちを外す。「要対応」の定義（用語集）を、許可待ち・質問待ちにする。ブラウザのタブのタイトルの件数も、同じ定義にする
- **機能 001 の受け入れ条件の置き換え**: 状態順の並び（AC-001-9）、件数サマリー（AC-010-3）、要対応のみの絞り込み（AC-010-5）、返答待ちの強調（AC-010-1・2）は、機能 006 の受け入れ条件に置き換える。機能 002・003 の「一覧の行に出す」は、「詳細に出す」に読み替える
- **状態の変化に気づく手段が減る**: 状態順をやめたので、許可待ちになったセッションが画面の上に来ることはない。気づく手段は、行の色と札、帯とプロジェクトの件数バッジ、タブのタイトルの件数になる。折りたたんだ帯にも件数が残るので、見落としにくいが、一覧の先頭を見れば分かる、という手軽さはなくなる
- **結果の行の内容**: 会話の中に、許可した入力や回答の内容まで残す表示（試作にある）は、本文を Hub が持たないという NFR-009 と衝突する。会話ログ（JSONL）から読む機能 004（REQ-007）の範囲とし、機能 006 では、ブラウザのメモリ内の「結果の行」（ツールの名前と結果）にとどめる
- **モデル名・使用率（5h / 7d）の表示**: 試作にあるが、取得経路が未検証なので、この ADR の範囲に含めない（`../10-requirements/open-questions.md`）
- **入力欄の自動伸縮**: CSS の `field-sizing: content` に頼る。未対応のブラウザ（Firefox・Safari は対象外。NFR-010）では、1 行のまま広がらない。Chrome / Edge では動く
- 画面のテスト（SSR・jsdom）と、`src/web/` の部品・ロジックの作り直しが必要になる
