# 0011: チャネルサーバーは 1 つの実装で、起動引数により操作モードを切り替える

- ステータス: Accepted
- 日付: 2026-10-09

## 背景
指示の送信（ADR 0001）と許可応答（ADR 0002）には、チャネルサーバーがチャネル機能（`claude/channel`）を宣言する必要がある。
実機で、次のことが分かっている（2026-10-09）。

- チャネル機能を宣言したサーバーは、起動のたびに `--dangerously-load-development-channels server:<名前>` が要る。付けないと、サーバーは動くが通知は黙って捨てられる
- 宣言しない通常の MCP サーバーは、フラグも警告も要らない（ADR 0006）
- 同じセッションに複数のチャネルサーバーがあると、Hub への登録が重複する（同じ `session` の新しい `/poll` が古い `/poll` を終わらせる）

一覧だけを使うセッションに、毎回フラグを要求したくない。一方、指示を送りたいセッションでは、チャネル機能が要る。

## 選択肢
1. 常にチャネル機能を宣言する（全セッションでフラグが必要）
2. 一覧用と操作用の 2 つの別サーバーにする（名前を分ける）
3. 実装は 1 つ（`channel.mjs`）。起動引数 `--channel` があるときだけチャネル機能を宣言する

## 決定
3 を採用する。

- `channel.mjs` は、引数なしでは今までどおり（機能の宣言なし。一覧と生存確認だけ）
- 引数 `--channel` を付けた定義では、`claude/channel` と `claude/channel/permission` を宣言し、指示の通知と許可の中継を行う
- サーバーの名前は、どちらも `coders-hub` に揃える。起動時のフラグは `server:coders-hub`
- 起動用スクリプトが、操作モードのときだけ `--channel` 入りの MCP 設定とフラグを渡す。一覧だけのときは、引数なしの設定を渡す
- 操作モードかどうかは、`/poll` の本文（`channel: true`）で Hub に伝える

## 理由
- 1 セッションに 1 つのサーバーだけが動くので、登録が重複しない
- 一覧だけの使い方は、今のまま手軽に起動できる
- 実装が 1 つで、ポーリングや生存確認のコードを共有できる

## 影響・トレードオフ
- 操作モードで起動したのにフラグを付け忘れると、サーバーは動くが通知は捨てられる。Hub は「操作できる」と見なしてしまうため、届いたかどうかを別の方法で確認する（機能 002 の受信確認）
- 起動用スクリプトの側に、モードを切り替える仕組みが要る（`docs/setup.md` に書く）
- 要検証: チャネル機能を宣言したサーバーを、フラグなしで起動したときの挙動（エラーか、警告か、黙って無効か）。機能 002 の T0 で確認する
