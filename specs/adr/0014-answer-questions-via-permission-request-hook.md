# 0014: モデルからの質問（AskUserQuestion）への回答は、PermissionRequest フックで返す

- ステータス: Accepted
- 日付: 2026-10-10

## 背景
機能 003（許可応答）の実機確認（`spikes/probe-channels.mjs`、`claude` 2.1.295、Windows）で、次のことが分かった。

- チャンネルの許可中継（ADR 0002）は、`Bash` / `Write` / `Edit` の許可要求では `permission_request` が届き、ID ごとに `allow` / `deny` を返せる
- `AskUserQuestion`（モデルからの質問）は、**許可中継に流れてこない**（質問画面が出ている間、要求の一覧は空のまま）
- 一方、`AskUserQuestion` でも `PermissionRequest` フックは発火する（ADR 0010 の「質問待ち」の判定に使っている）

ダッシュボードから質問に答えられないと、質問待ちのセッションはターミナルに戻らない限り進まない。

## 選択肢
1. 質問への回答はしない。ダッシュボードは「質問待ち」の表示と通知だけにする（ADR 0010 の現状）
2. `PermissionRequest` フックが Hub に質問を送り、Hub が返した答えをフックの出力で `claude` に返す
3. 回答を、通常の指示（チャンネルの通知）としてモデルに送る

## 決定
2 を採用する。未検証の2点（下記）は、機能 003 の仕様の確認項目として扱う。

- `AskUserQuestion` 用の `PermissionRequest` フック（`matcher: "AskUserQuestion"`）が、質問（`tool_input.questions`）を Hub に送る
- フックは、Hub から答えが返るまで待つ。答えが返れば、許可（`behavior: "allow"`）に `updatedInput`（元の入力に `answers` を足したもの）を付けて出力する
- `answers` は、質問文をキー、答えの文字列を値とする。複数選択はカンマ区切り、自由入力は入力した文字列をそのまま渡す
- 待ちきれなかった場合（タイムアウト）は、何も出力せずに終了する。通常の質問画面に任せる
- 質問画面は、フックが待っている間もターミナルに出る。ターミナルで先に答えられた場合、フックは終了せずに待ち続ける。そのあとに Hub が答えを返しても、無視される（実機で確認）
- Hub は、質問が片付いたこと（ターミナルで答えた・拒否した・`claude` が終了した）を、`AskUserQuestion` の `PostToolUse` フックや、フックの接続切れ、会話ログ（ADR 0007）で検知して、画面の質問を閉じる

## 理由
実機で次を確認した。

- フックの出力で答えを返すと、質問画面は出ず、モデルは答えを受け取る（画面表示: `User answered Claude's questions … Allowed by PermissionRequest hook`）
- フックが 20〜26 秒待ってから答えを返しても通る
- 3 問を一度に質問し、単一選択（`黄`）、複数選択（`りんご,みかん`）、自由入力（`太郎`）をまとめて答えられる
- 質問画面は、フックが待っている間も、頼んだ直後に出る
- 画面で答えても、待っているフックは終了せず、タイムアウトまで残る。そのあとに Hub が答えを返しても、二重に答えが渡ることも、エラーになることもなかった（モデルは画面で選んだ答えを受け取った）
- 画面で答えると、`AskUserQuestion` の `PostToolUse` フックが答えの直後に発火する。`tool_response` に `questions`、`answers`（質問文 → 答え）、`annotations` が入る。フックが待ち続けていても発火する
- 画面で拒否（Esc）すると、待っているフックは通知なしに強制終了される（`signal` も `exit` も記録されない）

1 は何もしないので確実だが、質問のたびにターミナルへ戻る必要がある。3 は質問への答えとしてモデルに渡るかが不明確で、質問が未解決のまま残る。

## 影響・トレードオフ
- フックが Hub を待つので、**フックの待ち時間の上限**（フックの `timeout`）を決める必要がある。Hub が止まっているときは、待たずに通常の画面へ任せる
- ターミナルで答えられても、フックの接続は切れない。拒否のときだけ強制終了で切れる。Hub は接続の切断だけでは質問を閉じられないため、別の手がかり（`PostToolUse` フック、会話ログ）が要る
- Hub が遅れて返した答えは捨てられるだけで害はない。ただし、画面には答え済みの質問を出し続けないよう、Hub 側でも閉じる
- フックが残す待ちの状態（ファイルなど）は、終了時に消えないことがある。Hub は古い質問を新しい質問で置き換える
- 質問の選択肢に出ないラベルを送ると、どう扱われるかは未確認。画面は、選択肢の `label` か自由入力だけを送る
- 質問と答えの本文を、Hub のメモリに持つ。答えを返した時点で破棄する（NFR-009）

## 未検証
- 選択肢にない文字列を、複数選択の答えに混ぜたときの扱い
- 複数のセッションが同時に質問したときの、Hub とフックの対応づけ
