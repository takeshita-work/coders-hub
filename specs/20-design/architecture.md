# アーキテクチャ

- ステータス: Draft
- 参考: `docs/research/claude-code-mechanisms.md`（フック・Channels の仕様）

## 構成

```
[ブラウザ（ダッシュボード）]
        │  HTTP / WebSocket（:8766、外部公開する場合はここだけ）
        ▼
[Coders Hub 本体（Node.js ローカルサーバー）]
        ▲  内部通信（127.0.0.1:8765、外部公開しない）
        │
        ├─ チャネルサーバー ⇄ stdio ⇄ claude（アカウントA・セッション1）
        ├─ チャネルサーバー ⇄ stdio ⇄ claude（アカウントA・セッション2）
        ├─ チャネルサーバー ⇄ stdio ⇄ claude（アカウントB・セッション1）
        └─ フック用スクリプト（各セッションのイベントごとに起動）
```

## 部品と責務

| 部品 | 役割 | 規模 |
|---|---|---|
| Hub 本体（`hub.mjs`） | セッション一覧・状態管理・指示の振り分け・許可応答・ダッシュボード | 大 |
| チャネルサーバー（`channel.mjs`） | セッションと本体をつなぎ、指示・許可応答をセッションへ届ける | 小 |
| フック用スクリプト（`hook.mjs`） | 状態変化を本体へ通知する | 小 |
| 待機スクリプト（`wait.mjs`） | asyncRewake 方式の代替経路 | 小 |

ロジック（作業中の判断、指示の保留、宛先の振り分け）は Hub 本体に集約し、接続部品は薄く保つ。他ツール対応時は、ツールごとの接続部品を追加する。

## MVP の構成
- 使う部品: Hub 本体、フック用スクリプト、チャネルサーバー
- チャネルサーバーは登録と生存確認だけを担う。指示送信・許可応答は「次」の段階（ADR 0006）
- 待機スクリプト（`wait.mjs`）は MVP では使わない
- 画面への反映は WebSocket で、本体からブラウザへ即時にプッシュする（NFR-003: 3 秒以内）

## 指示の送信（機能 002）の構成
- チャネルサーバーは 1 つの実装で、引数 `--channel` のときだけチャネル機能を宣言する（ADR 0011）。名前はどちらも `coders-hub`
- 画面から Hub 本体へ指示を送り、Hub 本体が返答待ちになるまで保留して、`/poll` の応答として 1 件ずつ渡す（ADR 0013）。チャネルサーバーが通知としてセッションへ送る
- 届いたかは、会話ログの記録（`id` 属性）で確認する。画面用の書き込み API は ADR 0012 で守る
- 詳細は `../30-features/002-send-instruction/plan.md`、API は `api/README.md`

## 画面側の技術
- React。esbuild でバンドルした静的ファイルを Hub 本体（:8766）が配信する（ADR 0008。リポジトリのパスに `#` を含み、Vite の開発サーバーが動かないため）
- テストは `node:test`（Hub 本体・フック・チャネル・画面の部品とも）
- 本体との状態同期は WebSocket
- Hub 本体・チャネルサーバー・フックは Node.js（`.mjs`）

## 採用する仕組み

| 機能 | 仕組み | 関連 ADR |
|---|---|---|
| 状態を知る | フック（UserPromptSubmit / Stop / Notification） | 0003 |
| 指示を送る | Channels（主）／ asyncRewake の Stop フック（代替） | 0001 |
| 許可に応答する | Channels の許可中継 | 0002 |
| 会話内容を見る | JSONL の監視（補助） | - |

## セッション管理

- チャネルサーバーはセッションごとに 1 つ起動し、自分を起動したセッションとだけつながる
- ポートを使うのは Hub 本体だけ（内部 8765、画面 8766）。チャネルサーバーは本体へ接続しに行く（ロングポーリング約 30 秒）
- 識別: アカウント=`CLAUDE_CONFIG_DIR`、セッション=`CLAUDE_CODE_SESSION_ID`（フック側は `session_id`）、プロジェクト=cwd
- 登録・生存確認: ポーリングのたびに自己情報を送る。一定時間来なければ一覧から外す。本体再起動後も自動復元。stdin が閉じたら終了通知
- 本体の自動起動: チャネルサーバーが `/health` を確認し、つながらなければ本体を別プロセスで起動。ポート確保で本体は常に 1 つ
- MCP はユーザースコープに登録せず、起動時の `--mcp-config` で指定する（無効なセッションで通知が黙って捨てられるのを防ぐ）

## 内部 API（想定）

| エンドポイント | 呼び出し元 | 内容 |
|---|---|---|
| `GET /health` | チャネルサーバー | 本体の起動確認 |
| `POST /poll` | チャネルサーバー | 登録・生存確認・指示の受け取り |
| `POST /permission` | チャネルサーバー | 許可プロンプトの受け取り |
| `POST /event` | フック用スクリプト | 状態変化の通知 |
| `POST /wait` | 待機スクリプト | 指示の受け取り（asyncRewake 方式） |

詳細は `api/` に定義する。
