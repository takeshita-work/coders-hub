# 003 許可・質問への応答

- ステータス: Implemented（2026-10-10。自動テスト 339 件、実機の確認は `./acceptance.md`）
- 対応要件: REQ-004, REQ-005
- 関連 NFR: NFR-003, NFR-009
- 関連 ADR: 0002（許可応答に許可中継）、0010（質問待ち）、0011（操作モード）、0012（画面用の書き込み API の保護）、0014（質問への回答にフック）
- 前提の実機確認（`claude` 2.1.295、Windows。検証用: `spikes/probe-channels.mjs`、`spikes/probe-verdict.mjs`、`spikes/probe-ask-hook.mjs`）:
  - 許可待ちになると、チャネルサーバーに許可要求（`request_id`・`tool_name`・`description`・`input_preview`）が届き、ID ごとに許可／拒否を返せる。拒否はモデルに伝わる
  - 許可要求は 1 件ずつ順に届く（同時に 2 件は届かなかった）
  - `input_preview` は 3,268 文字までは切れずに届く。約 3,600 文字を超えると、中間が `⋯ N code points elided ⋯`（N は省略した文字数）に置き換わり、全体で約 3,600 文字になる（先頭 約 2,000 文字・末尾 約 1,500 文字が残る）。全文は許可中継では得られない
  - 質問（`AskUserQuestion`）は許可中継に流れない。`PermissionRequest` フックで答えを返せる（ADR 0014）

## 目的
ダッシュボードから、許可待ちのセッションに「許可」「拒否」を返し、質問待ちのセッションの質問に答えられるようにする。ターミナルまで戻らずに、止まっているセッションを再開できる（成功の基準「操作できる」）。

## 用語
`../../00-product/glossary.md` に従う。「許可要求」は、ツールの実行の許可を求めるもの。「質問」は、モデルが `AskUserQuestion` で利用者に選択肢を示して答えを求めるもの。

## 振る舞い

### 応答できるセッション
- 操作モードのセッションだけが、許可・質問に応答できる（許可は許可中継、質問は `AskUserQuestion` 用のフックの設定が必要）
- 操作モードでないセッションでは、応答の操作ができず、理由が分かる。許可待ち・質問待ちの表示は、これまでどおり出る

### 許可要求への応答（REQ-004）
- 許可待ちの行に、許可要求の内容を表示する
  - ツール名（`Bash`・`Write`・`Edit` など）
  - 入力の内容（コマンド、ファイルパス、変更内容）。長いときは折りたたみ、開いて見られる。届いた範囲だけを表示し、省略されているときは、省略があることと省略された文字数を示す（全文は表示できない）
  - `description`。`Bash` ではモデルが付けた説明、`Write`・`Edit` では固定の文なので、補助として表示する
- 「許可」「拒否」を押すと、その要求に応答が返り、セッションが再開する。拒否はモデルに伝わる
- 許可要求が複数あるときは、1 件ずつ順に出る。ID ごとに別々に応答できる

### 質問への回答（REQ-004、ADR 0014）
- 質問待ちの行に、質問文と選択肢（ラベルと説明）を表示する
- 質問ごとに、選択肢から選べる。複数選択の質問は複数選べる。自由入力ができる質問は、文字列を入力できる
- すべての質問に答えて送信すると、答えがセッションに渡り、質問待ちが終わる。モデルは答えを受け取って続ける
- 答えを送らずに待っていると、フックのタイムアウトで、通常の質問画面（ターミナル）に任せる状態に戻る。画面の質問は閉じて、理由を表示する

### ターミナルとの共存（REQ-005）
- ターミナルの許可画面・質問画面は、アプリが開いていても通常どおり出て、操作できる
- ターミナルで先に応答したら、アプリの許可要求・質問は自動で閉じ、「ターミナルで応答済み」と分かる。許可要求は、状態の変化（`PostToolUse` や拒否の検知）で、質問は `AskUserQuestion` の `PostToolUse` で閉じる（ADR 0014）
- アプリが遅れて返した応答は、無視されるだけで害はない（許可・質問とも実機で確認）。画面は、応答済みの要求に応答の操作を出さない

### 応答の結果
画面に、要求ごとの結果を表示する。

| 結果 | 意味 |
|---|---|
| 応答待ち | 許可要求・質問が届いている |
| 許可しました / 拒否しました | アプリから応答を返した |
| 回答しました | アプリから質問に答えた |
| ターミナルで応答済み | ターミナルで先に応答された |
| 時間切れ | 質問のフックが待ちきれず、ターミナルに任せた |
| 応答できませんでした | セッションが閉じた・操作モードでない・不正な入力など。理由を表示する |

- 結果の表示は、その画面を開いている間だけ。再読み込みで消える

### 保存しない（NFR-009）
- 許可要求の入力と質問の本文は、応答するまでのあいだだけ Hub 本体のメモリにある。応答した時点で破棄する
- 応答の履歴は、Hub 本体にも画面にも保存しない

### 安全面（ADR 0012）
- 応答の操作は、他のサイトのページからは行えない
- 外部公開はしない（REQ-006 は別の機能）

## 受け入れ条件

### 許可要求への応答（REQ-004）
- AC-004-1: 許可待ちの行に、ツール名と入力の内容が表示される。長い入力（3,000 文字以上）は、折りたたみと、届いた範囲の表示ができる。入力が省略されて届いたときは、省略があることと省略された文字数が表示される
- AC-004-2: 「許可」を押すと、ツールが実行され、セッションが作業中に戻る
- AC-004-3: 「拒否」を押すと、ツールは実行されず、モデルが拒否されたことを返答する
- AC-004-4: 許可要求が続けて出ても、ID ごとに別々の応答を返せる（1 件目を許可、2 件目を拒否、など）
- AC-004-5: 操作モードでないセッションでは、応答の操作ができず、理由が表示される
- AC-004-6: 応答は、押してから 3 秒以内にセッションへ届く（NFR-003 に準じる）

### 質問への回答（REQ-004）
- AC-004-7: 質問待ちの行に、質問文と選択肢（ラベル・説明）が表示される
- AC-004-8: 単一選択の質問に答えると、選んだ選択肢がセッションに渡る
- AC-004-9: 複数の質問、複数選択、自由入力を含む質問に、まとめて答えられる
- AC-004-10: 回答が届くと、画面の質問待ちが終わり、セッションが作業を再開する
- AC-004-11: 答えがないままフックの待ち時間を過ぎたら、画面の質問を閉じ、「時間切れ」と表示する。ターミナルの質問画面は残る

### 共存（REQ-005）
- AC-005-4: アプリが開いていても、ターミナルの許可画面・質問画面で通常どおり応答できる
- AC-005-5: ターミナルで先に許可・拒否したら、アプリの許可要求が閉じ、「ターミナルで応答済み」と表示される。応答済みの要求に、応答の操作が出ない
- AC-005-6: ターミナルで先に質問に答えたら、アプリの質問が閉じ、「ターミナルで応答済み」と表示される
- AC-005-7: ターミナルで質問を拒否（Esc）したら、アプリの質問が閉じる
- AC-005-8: アプリが遅れて応答しても、二重の実行やエラーにならない

### 保存・安全
- AC-004-12: 許可要求の入力と質問の本文は、応答した後に Hub 本体のメモリに残らない（NFR-009）
- AC-004-13: 他のオリジン、不正な `Host`、独自ヘッダーなしのリクエストでは、応答できない（403。ADR 0012）

## 対象外
- 許可要求の入力の全文の表示（許可中継では省略されて届く。全文が必要なら、`PermissionRequest` フックから入力を送る別の機能として検討する）
- 許可の永続化（「今後は常に許可」「このセッションでは許可」など）。1 件ずつの許可・拒否だけ
- 許可の規則（`permissions` の設定）の編集
- プランの承認など、`AskUserQuestion` 以外の応答を求める操作（別の機能。調査は `open-questions.md`）
- 応答の履歴の保存、一括の許可・拒否
- ブラウザ通知・スマホ通知（画面内の表示のみ）
- 外部からの利用・認証（REQ-006）
