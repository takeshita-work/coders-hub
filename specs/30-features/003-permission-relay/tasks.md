## フェーズ 0: 検証（実機。`spikes/` を使う）

済んだ検証（結果は plan の「実機で分かったこと」と ADR 0014）:
- [x] T0-1 ★ 許可／拒否の中継: `allow`・`deny` が効き、拒否がモデルに伝わる
- [x] T0-2 ★ 許可要求が複数続くとき: 1 件ずつ順に届き、ID ごとに応答できる
- [x] T0-3 ★ 質問が許可中継に流れるか: 流れない
- [x] T0-4 ★ 質問への代理回答: `PermissionRequest` フックの `updatedInput.answers` で通る。待ちは 20〜26 秒でも通り、複数質問・複数選択・自由入力も通る
- [x] T0-5 ★ 質問に先にターミナルで答えたとき: フックは残り、遅れた答えは無視される。`PostToolUse` が発火し、`tool_response.answers` に答えが入る
- [x] T0-6 ★ 入力の表示: `Bash`・`Write`・`Edit` の `tool_name`・`description`・`input_preview`。3,268 文字まで切れない

残り:
- [x] T0-7 ★ 先にターミナルで許可・拒否したあと、遅れて `allow`／`deny` を返したときの挙動（`spikes/probe-verdict.mjs`）
  - 結果: 害なし。許可（Yes）のあとに遅れた `allow` → 実行は 1 回だけ。拒否（No）のあとに遅れた `allow` → 実行されない（拒否は覆らない）。許可のあとに遅れた `deny` → 実行済みの結果は変わらない。ただし、ターミナルで先に答えても、`claude` はチャネルに「解決済み」を通知しない。要求は検証用サーバーに残り続けるため、Hub 側で閉じる必要がある
- [x] T0-8 ★ 質問の答えに選択肢にない文字列を送ったときの扱い（`spikes/probe-ask-answer.mjs`）
  - 結果: 単一選択に `紫`、複数選択に `りんご,バナナ` を送ると、そのまま通り、モデルは「Other の自由入力」として受け取る。空の答え（`""`）もエラーにならず通るが、モデルは「回答がなかった」と受け取る。→ Hub は選択肢の外を弾かない。空の答えは送れないようにする（T1-2）
- [x] T0-9 ★ 複数セッションが同時に質問したときの対応づけ
  - 結果: 2 つのセッションが同時に質問しても、フックの入力の `session_id` で区別でき、答えは取り違えられずに別々のセッションへ渡る（動物 → 猫、色 → 青）。順序を逆にして答えても影響しない
- [x] T0-10 ★ 許可要求の `input_preview` の上限（10,000 文字以上の入力）
  - 結果: 約 12,000 文字のコマンドは、全体で約 3,600 文字に省略されて届く。先頭 約 2,000 文字（`{ "command": "echo '` から `#00199----#00` まで）と末尾 約 1,500 文字を残し、間を `
⋯ 8509 code points elided ⋯
`（省略した文字数つき）に置き換える。3,268 文字は切れずに届いたので、上限は 3,268〜約 3,600 文字の間。40,000 文字は `echo` では実行できず（Windows のコマンドライン長の上限）、確認していない。→ 全文は許可中継だけでは得られない。`PermissionRequest` フックの入力（`tool_input`）には全文が入る
