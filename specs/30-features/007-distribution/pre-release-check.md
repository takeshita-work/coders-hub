履歴には、会話ログ（JSONL）・フックの記録・画面のスクリーンショットは**含まれていない**（`.gitignore` と、ファイルの一覧で確認）。仕様・受け入れ確認に書いた、依頼の文面の例（`Bash で ls を実行して` など）は、機密ではない。

## 対応の選択肢
| 選択肢 | 内容 | 影響 |
|---|---|---|
| **A. 作業ツリーだけ、置き換える（実施）** | ユーザー名・アカウント名・取引先らしい名前・起動スクリプト・作業フォルダのパスを、ダミーの名前（`dev`・`.claude-main`・`.claude-sub`・`sub-*`・`D:\work\…`・`<起動用スクリプト>`）に置き換える。以後のコミットと、配布物には、含まれない | 履歴（過去のコミット）には、残る。履歴の書き換えはしないので、安全 |
| B. 履歴も書き換える | `git filter-repo` で、全コミットから該当の文字列を置き換え、強制 push する | 公開済みのリポジトリで、全コミットの ID が変わる。フォーク・クローン・リンクが壊れる。取り消せない |
| C. 何もしない | そのまま公開を続ける | 低リスクだが、個人名・取引先らしい名前が残る |

## 判断の目安
- 今回の内容は、秘密情報ではなく、パスやアカウント名の「例」の範囲。履歴の書き換え（B）まで行う必要は、低いと考えられる。
- 取引先などの名前が、公開してはいけないものであれば、B を検討する（すでに公開済みなので、早いほど影響が小さい）。
