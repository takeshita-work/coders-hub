# 007 配布（GitHub リリースと単一の exe）

- ステータス: Approved（2026-10-11）
- 対応要件: REQ-011
- 関連 NFR: NFR-001, NFR-005, NFR-009
- 関連 ADR: 0018（配布の方式）、0020（Hub の起動の分離）、0019（ポートの設定ファイル）、0021（設定ファイルの置き場所）、0011（操作モード）
- 手順の下書き: `../../../docs/setup.md`

## 目的
開発環境（Node.js・`npm`）のない人が、GitHub のリリースから入手した `coders-hub.exe` だけで、Coders Hub を使い始められるようにする。

この機能は、動作そのものは変えない。**入手と起動と設定の入れ方**を変える。

## 用語
`../../00-product/glossary.md` に従う。「配布物」は、リリースに添付する、個別のファイル（zip にはしない。ADR 0022）。

## 振る舞い

### 配布物
- GitHub のリリースに、次のファイルが、個別の資産として添付される（zip にはしない。ADR 0022）
  - `coders-hub.exe`: 本体（バージョンなしの固定名。`releases/latest/download/coders-hub.exe` が、常に最新を指す）
  - `README.txt`: 日本語。使い方・設定・SmartScreen の開き方・更新・アンインストール
  - `config.example.json`: 設定の見本。読み込まれない。使うときは `config.json` にコピーする（リリースに `config.json` は含めない。更新で、利用者の設定を上書きしないため）
  - `LICENSE`（MIT）、`THIRD_PARTY_NOTICES.txt`（exe に含まれる Node.js と npm パッケージのライセンス表示。画面と exe の両方）、`SHA256SUMS.txt`（`coders-hub.exe` の SHA-256）
- リリースには、変更点（リリースノート）と、`coders-hub.exe` の SHA-256 が書かれる
- 対象は Windows x64（NFR-001）

### 使い方（利用者）
1. リリースから `coders-hub.exe` をダウンロードし、書き込めるフォルダに置く（置き場所は、移動しない）。設定を変えるときは、`config.example.json` を `config.json` にコピーする
2. `coders-hub.exe setup` を実行すると、`claude` に入れる設定（フックと、チャネルサーバーの MCP 設定）が、この exe のパスを指す形で、表示される（操作モード用の設定も出す）
3. **`coders-hub.exe` をダブルクリックして、Hub を起動する**（ウィンドウは出ない）。ログイン時に自動で起動したければ、利用者が、スタートアップ・タスク スケジューラに登録する
4. `claude` を起動する（`--mcp-config` で、チャネルサーバーを付ける）。チャネルサーバーは、Hub を起動しない
5. ブラウザで、画面を開く（既定の URL は、README に書く）。Chrome / Edge の「アプリとしてインストール」も使える
6. 更新は、画面の「Hub を終了」で Hub を止め、新しいリリースの `coders-hub.exe` を置き換える。`config.json` は触らない（リリースに含まれないので、上書きされない）

### サブコマンド
- 引数なし・`start`: Hub を、ウィンドウなしで、切り離して起動し、すぐ終了する。すでに動いていれば、何もしない。出力は `%LOCALAPPDATA%\coders-hub\hub.log` に追記する（ダブルクリックを含む）
- `hub`: Hub 本体を、前面で動かす（確認・不具合調査用。ログは標準出力）
- `hook`・`ask-hook`: フックとして、標準入力のイベントを Hub へ送る（`claude` が起動する）
- `channel [--channel]`: チャネルサーバー（MCP サーバー）として動く（`claude` が起動する）。`--channel` で操作モード（ADR 0011）。Hub は起動しない
- `setup`: `claude` に入れる設定を出力する
- `version`: バージョンを表示する
- 配布版の exe は、ウィンドウなし（GUI）の形式。ターミナルで直接実行すると出力が出ないので、`setup`・`version` は、`| more` のようにパイプへ渡す（ADR 0020）

### Hub の起動と終了（ADR 0020）
- チャネルサーバーは、Hub を起動しない。Hub がなくても落ちず、Hub が動き始めたら、再接続して登録する
- 起動は、利用者が行う（ダブルクリック、`start`、スタートアップ、タスク スケジューラ）。自動起動の設定は作らない
- 終了は、画面の「フィルター・ソート」のパネルの「Hub を終了」（確認つき）。ほかに、タスクマネージャー。終了後は、チャネルサーバーが起動し直すことはない

### 画面のファイル
- 画面（HTML・JS・CSS）は、exe に埋め込まれ、Hub が配信する。別のファイルを、横に置く必要はない

### ビルドとリリース（開発者）
- タグ `v<バージョン>` を push すると、GitHub Actions が、次を行う: 依存の取得、テスト、画面のビルド、exe の作成、動作確認（`version`・`start` による起動、`/health`、画面、終了 API）、資産と SHA-256 の作成（zip にはしない）、リリースの作成と添付
- バージョンは、`package.json` の `version` と、タグが一致していること。一致しなければ、リリースを作らない
- テストが失敗したら、リリースを作らない

## 受け入れ条件

AC の番号は、要件 REQ-011 に対応する。

### 配布物
- AC-011-1: タグの push で、GitHub のリリースに、個別の資産（AC-011-2）が添付される。リリースに変更点がある
- AC-011-2: 資産に、`coders-hub.exe`・`README.txt`・`config.example.json`・`LICENSE`・`THIRD_PARTY_NOTICES.txt`・`SHA256SUMS.txt` が含まれる（`config.json` は含まれない）。`THIRD_PARTY_NOTICES.txt` に、Node.js と、束ねた npm パッケージ（画面と exe の両方）のライセンス文が入る
- AC-011-3: `SHA256SUMS.txt` の値が、資産の `coders-hub.exe` の SHA-256 と一致する
- AC-011-4: `package.json` の `version` とタグが一致しないと、リリースが作られない。テストが失敗しても、作られない

### exe の動作
- AC-011-5: Node.js のない Windows で、`coders-hub.exe version` がバージョンを表示する
- AC-011-6: `coders-hub.exe hub` で、Hub が起動し、`/health` が `ok` を返し、画面（`/`）が表示される。画面のファイルは、exe に埋め込まれたものが配信される
- AC-011-7: 画面の配信は、埋め込まれたファイル以外（フォルダの外）を返さない（403・404）
- AC-011-8: `coders-hub.exe setup` が、exe のパスを指すフックの設定と MCP の設定を出力する。パスの区切りは、シェルで壊れない形になる。操作モード用の設定も出る
- AC-011-9: `coders-hub.exe hook` と `ask-hook` が、`node` 版と同じ動作をする（標準入力のイベントを Hub へ送る。失敗しても `claude` を妨げない）
- AC-011-10: `coders-hub.exe channel` が、MCP サーバーとして動き、Hub に登録される。`--channel` で操作モードになる
- AC-011-11: Hub が動いていないとき、チャネルサーバーは、Hub を起動せず、落ちずに待つ。Hub が動き始めたら、再接続して登録する（AC-011-23 が置き換え）
- AC-011-12: 本物の `claude` で、配布版の exe を使って、一覧・指示の送信・許可・質問への応答・会話の表示が動く（機能 001〜004、006）
- AC-011-13: 開発時（`npm start`・`node …`）の動作は、これまでと変わらない

### 設定（ポート）（ADR 0019）
- AC-011-15: 設定ファイル（`coders-hub.exe` と同じフォルダの `config.json`）の `internalPort`・`uiPort` が、Hub・フック・チャネルサーバーのポートになる。キーは省略でき、省略したほうは既定値。他のキーは無視する
- AC-011-16: 環境変数（`CODERS_HUB_INTERNAL_PORT`・`CODERS_HUB_UI_PORT`）は、設定ファイルより優先する
- AC-011-17: 設定ファイルがなければ、既定値（内部 47765・画面 47766）を使う
- AC-011-18: 設定ファイルが壊れている・ポートが不正なときは、ファイルのパスを含むエラーにする（黙って既定値に戻さない）。フックは、失敗しても `claude` を妨げない
- AC-011-19: 設定ファイルのパスは、環境変数 `CODERS_HUB_CONFIG`、なければ `coders-hub.exe` と同じフォルダの `config.json`（ADR 0021）。開発時（`node` で起動）は、`CODERS_HUB_CONFIG` を指定したときだけ読む

### Hub の起動と終了（ADR 0020）
- AC-011-20: 引数なしの `coders-hub.exe` と `start` は、Hub が動いていなければ、ウィンドウなしの Hub を切り離して起動し、すぐ終了する。起動した Hub は、起動元を終了しても残る
- AC-011-21: すでに Hub が動いているときの `start` は、何もしない（2 つ目を起動しない）
- AC-011-22: ウィンドウなしの Hub の出力は、`%LOCALAPPDATA%\coders-hub\hub.log` に追記される。起動のとき 1 MB を超えていたら、作り直す。設定ファイルの誤りなどで Hub が起動できないときも、理由が `hub.log` に残る
- AC-011-23: チャネルサーバーは、Hub を起動しない。Hub が止まっても落ちず、動き始めたら再接続して登録する
- AC-011-24: `POST /api/shutdown`（ADR 0012 の保護あり）で、Hub が、応答を返してから終了する。保護を満たさない要求は 403。終了後は、チャネルサーバーが Hub を起動し直さない
- AC-011-25: 画面の「フィルター・ソート」のパネルに「Hub を終了」がある。押すと確認が出て（動いているセッションが一覧から消える旨）、「終了する」で `POST /api/shutdown` を呼ぶ。「やめる」では何もしない
- AC-011-26: 配布版の exe は、ウィンドウなし（GUI）の形式で、パイプ経由の標準入出力（`version`・`hook`・`channel`）が動く。ダブルクリックでコンソールのウィンドウが出ない

### 文書
- AC-011-14: README に、入手・展開・設定・起動・更新・アンインストール・SmartScreen の開き方・困ったとき（ポート・古い Hub）と、ポートの変え方（設定ファイル）、Hub の起動・自動起動の登録・終了が書かれている

## 対象外
- 署名（コード署名証明書）
- アプリ内の更新の案内・自動更新（ADR 0018）
- Windows 以外・ARM 版
- インストーラー（MSI・自動起動の登録・スタートメニューの登録）。必要になったら別の機能にする
- 外部公開・認証（REQ-006、機能 005）

## 決定済み
- ポートは、設定ファイルでも変えられる。既定は 47765 / 47766（ADR 0019、2026-10-12）
- ライセンスは MIT（2026-10-11）。著作権者は `takeshita-work`
