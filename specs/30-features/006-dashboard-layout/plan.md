# 006 ダッシュボードの画面構成 実装計画

- ステータス: Approved
- 対応 spec: ./spec.md
- 関連 ADR: 0015
- 参考: 試作 `../../20-design/screens/mockup/index.html`（見た目の基準。ダミーデータのみで Hub には接続しない）

## 方針
Hub の変更は `startedAt` の追加だけ。残りは `src/web/` の作り直し（並べ替え・ツリー化・レイアウト・スマホ）で、WebSocket のメッセージと書き込み API（ADR 0012）は変えない。試作の HTML・CSS を実装の出発点にし、状態・データの扱いは既存の `logic.mjs`・`client.mjs` を使う。

## 部品と変更

| 部品 | 変更 |
|---|---|
| `src/hub/sessions.mjs` | セッションに `startedAt` を持たせる。初めて見た時刻で初期化し、状態ファイルの `startedAt` が読めたら置き換える |
| `src/hub/status-monitor.mjs` | 状態ファイルの `startedAt` をストアへ渡す（読むのは `sessionId`・`status`・`statusUpdatedAt` に加えて `startedAt`。ADR 0009 の非公開ファイルへの依存が 1 項目増える。読めないときは何もしない） |
| `src/web/logic.mjs` | 一覧の組み立てを、状態順のグループから「アカウント → プロジェクト → セッション」のツリーに置き換える。ソート（プロジェクト名の昇順／降順、起動順の早い／遅い）、絞り込み（操作できるものだけ）、件数（許可待ち・質問待ち）、タブのタイトル（要対応＝許可待ち・質問待ち）。折りたたみ・ソート・絞り込みの設定の保存（localStorage）は引き続き行う |
| `src/web/components.mjs` | サイドバー（見出し・パネル・ツリー・行・許可ボタン）と、詳細（見出し・会話・カード・結果の行・保留中の指示・入力欄・状態の行・「一番下へ」）に作り直す。要求のカードと指示欄は、一覧の行から詳細の会話へ移す |
| `src/web/styles.css` | 試作の CSS を元に、トークン（ライト・ダーク）、レイアウト、スマホ（800px）を実装する |
| `src/web/main.mjs` | 選択中のセッション、表示（一覧／詳細）、スクロール位置の保持（再描画で動かさない。新しい内容が増えたときだけ末尾へ） |

## 状態の持ち方（画面側）
- 選択中のセッション ID、スマホの表示（一覧／詳細）、パネルの開閉、折りたたみ、ソート、絞り込み
- 結果の行（許可・拒否・回答しました）と、送った指示の表示用の情報は、ブラウザのメモリ内。再読み込みで消える（spec の未決事項）。内容（入力・答え）は持たない

## リスクと確認
- 再描画のたびにスクロール位置が動く、入力中の文字が消える、といった問題が出やすい。入力欄とカード内の入力（質問の自由入力）の状態を、再描画で保つ
- 入力欄の自動伸縮（`field-sizing: content`）が使えないブラウザでは、1 行のまま。対象は Chrome / Edge（NFR-010）
- 30 セッション分のツリーの描画時間を、既存の負荷テスト（`tests/load.test.mjs`）で確認する
- 状態ファイルの `startedAt` は、実機で確認済み（`sessions/<pid>.json`、ミリ秒）
