# 001 セッション一覧

- ステータス: Draft
- 対応要件: REQ-001, REQ-008, REQ-010
- 関連 NFR: NFR-002, NFR-003, NFR-004, NFR-006, NFR-010
- 関連 ADR: 0003（状態取得にフック）、0004（単一 Hub 本体）、0006（MVP の生存確認）
- 画面の方針: `../../20-design/screens/README.md`

## 目的
複数アカウント・複数セッションの Claude Code の状態を一か所で見られるようにし、返答待ち・許可待ちのセッションにターミナルを巡回せずに気づけるようにする（成功の基準 1 位「気づける」）。

この機能は MVP の全体である。指示送信・許可応答・会話参照・外部公開は含まない。

## 用語
`../../00-product/glossary.md` に従う。状態は「作業中／返答待ち／許可待ち」の 3 つ。

## 振る舞い

### 一覧の表示
- ダッシュボードを開くと、稼働中の全セッションが一覧で表示される
- セッションは**アカウント（`CLAUDE_CONFIG_DIR`）ごとのグループ**にまとめて表示される
- 1 行に次の項目を表示する
  - 状態（作業中／返答待ち／許可待ち）
  - 状態の経過時間（その状態になってからの時間。例: 「返答待ち 5 分」）
  - プロジェクト（作業ディレクトリ）
  - 直近の発言（最後に送られたプロンプト）
  - セッション ID（短縮）
- 同じアカウント・同じプロジェクトに複数のセッションがあっても、別の行として区別できる

### 並び順
- グループ内は状態順: 許可待ち → 返答待ち → 作業中
- 同じ状態の中は、その状態になった時刻が新しい順

### 状態の更新
- セッションの状態が変わると、画面が自動で更新される（画面の再読み込みは不要）
- 新しいセッションが起動すると、自動で一覧に現れる
- セッションが終了すると、自動で一覧から外れる（強制終了を含む）
- Hub 本体が再起動しても、稼働中のセッションが自動で一覧に戻る

### 要対応の強調（REQ-010）
- 返答待ち・許可待ちの行は、作業中の行と区別できるよう強調表示される
- 通知は画面内の表示のみ。ブラウザ通知・スマホ通知・外部サービスへの通知は行わない
- 画面上部に、要対応の件数のサマリーを表示する（例: 許可待ち 2・返答待ち 3）
- 件数サマリーは、ブラウザのタブのタイトルにも反映される

### グループの折りたたみ
- アカウントのグループは折りたたみ・展開ができる
- 折りたたんだグループにも、要対応のセッション件数が表示される

### 状態での絞り込み
- 「すべて」と「要対応のみ（返答待ち・許可待ち）」を切り替えられる

## 受け入れ条件

### 一覧（REQ-001）
- AC-001-1: 稼働中の全セッションが、状態（作業中／返答待ち／許可待ち）付きで一覧に表示される
- AC-001-2: 1 行に、状態・状態の経過時間・プロジェクト・直近の発言・短縮セッション ID が表示される
- AC-001-3: セッションの状態が変わってから 3 秒以内に、画面上の状態が更新される（NFR-003）
- AC-001-4: 30 セッションが同時に稼働していても、一覧が表示・更新される（NFR-002）
- AC-001-5: セッションが閉じられると、1 分以内に一覧から外れる。強制終了した場合も同様（NFR-006）
- AC-001-6: Hub 本体を再起動すると、稼働中のセッションが追加の操作なしに一覧へ戻る（NFR-004）
- AC-001-7: 稼働中のセッションが 1 つもないとき、「セッションがありません」などの空の状態が表示される
- AC-001-8: 状態の経過時間が、画面を操作しなくても経過に合わせて更新される
- AC-001-9: グループ内の並びが、許可待ち → 返答待ち → 作業中、同じ状態の中は状態になった時刻が新しい順になっている

### 複数アカウント・複数セッション（REQ-008）
- AC-008-1: 複数のアカウントのセッションが、アカウントごとのグループに分かれて表示される
- AC-008-2: 同じアカウントの複数セッションが、別々の行として表示される
- AC-008-3: 同じアカウント・同じプロジェクトのセッションが複数あっても、セッション ID で区別できる
- AC-008-4: アカウントのグループは折りたたみ・展開でき、折りたたんだグループにも要対応の件数が表示される

### 要対応の強調（REQ-010）
- AC-010-1: 返答待ち・許可待ちの行が、作業中の行と視覚的に区別できる
- AC-010-2: 許可待ちと返答待ちが、互いに区別できる
- AC-010-3: 画面上部に、許可待ち・返答待ちそれぞれの件数サマリーが表示され、状態の変化に追従して更新される
- AC-010-4: 要対応の件数が、ブラウザのタブのタイトルに反映される。要対応が 0 件のときは件数が表示されない
- AC-010-5: 「要対応のみ」に切り替えると、返答待ち・許可待ちのセッションだけが表示される
- AC-010-6: ブラウザ通知・音・外部への通知は発生しない（MVP では行わない）

## 対象外
- セッションへの指示の送信（REQ-002, REQ-003）
- 許可プロンプトへの応答（REQ-004）
- 会話内容の参照（REQ-007）。一覧の「直近の発言」は最後のプロンプト 1 件のみ
- 外出先からの利用・認証・スマホ表示（REQ-006, NFR-010 のスマホ部分）
- ブラウザ通知・スマホ通知
- 状態・イベントの履歴の保存（NFR-009）
- VS Code 拡張・`claude --bg` のセッション
- Claude Code 以外のツールの表示（REQ-009 は構造の考慮のみ）

## 未決事項
- 要対応の強調表示の具体的な方法（色、アイコン、音の有無）
- 折りたたみ・絞り込みの状態をブラウザに保存するか
- 「直近の発言」の表示文字数と省略方法。プロンプトが空、または取得できないときの表示
- 絞り込みと折りたたみが両方あるときの優先関係
- 状態の経過時間の表示形式（「5 分」「1 時間 3 分」の区切り）
- 起動直後など、直近の発言や状態を取得できていないセッションの表示（状態不明を許すか）
- 許可待ちを検知する手段。MVP は Channels の許可中継を使わないため、`Notification` フックだけで足りるかの検証が必要（`../../10-requirements/open-questions.md`）
- Hub 本体に接続できないときの画面の表示
