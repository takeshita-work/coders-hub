- 実装方法には触れず、「何ができるべきか」だけを書く。
- 優先度: **MVP**（最初に作る）／ **次**（MVP の後）／ **設計のみ**（実装せず、構造だけ考慮する）

|---|---|---|---|

## 補足
- MVP は「一覧のみ」。成功の基準 1 位「気づける」に対応する（`../../00-product/vision.md`）。
- REQ-005（共存）は、MVP では状態を読み取るだけなので問題にならない。指示送信・許可応答を入れる段階で効いてくる。
- REQ-007 は JSONL の内部フォーマットに依存するため、直近の数件に限定する。全文参照はしない。
- 状態は 3 つで確定。セッションが閉じたら一覧から外す（`../../00-product/glossary.md`）。

- 一覧画面の方針（アカウントでグループ化、状態順の並び、件数サマリー、絞り込み、折りたたみ、表示項目）は `../../20-design/screens/README.md` に記載。MVP の機能 `001-session-list` で詳細化する。
- 一覧の「直近の発言」は `UserPromptSubmit` フックの入力から取得する。REQ-007（会話の参照、優先度「次」）の JSONL 参照とは別。
